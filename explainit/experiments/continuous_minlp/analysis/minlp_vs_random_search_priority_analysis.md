# Why random search beats MINLP on priority score (diabetes, set1/set2)

Analysis of `explainit/experiments/continuous_minlp/priority_methods/results/diabetes/{set1,set2}`
(run config: `epsilon=0.05`, `target_offset=-0.3`, MINLP `n_cfs=1`, random search `n_cfs=5`,
`max_iterations=10000`, `use_monte_carlo=true`).

No code was changed. All numbers below come from the committed result CSVs plus a read-only
re-evaluation of the per-feature priority contributions.

---

## 1. TL;DR

The comparison is not "optimisation loses to random". In most of the reported cells **MINLP never
returned an optimised point at all**: it returned its own *anchor exemplar*, i.e. a uniformly
random in-range point generated by `_generate_exemplar_in_range`, which is explicitly
priority-agnostic. Random search, by contrast, samples **proportionally to the priority functions**
(rejection sampling in `sample_numeric_value`, weight-proportional categorical choice), so a typical
accepted random draw already sits near the priority peaks.

Separating the MINLP rows by "was the returned CF the anchor or the SLSQP output?" splits the table
perfectly:

| MINLP returned | n | mean MINLP priority | mean random-search best priority | mean delta |
|---|---|---|---|---|
| SLSQP-optimised candidate | 5 | **5.34** | 4.32 | **+1.02 (MINLP wins 5/5)** |
| the random anchor exemplar | 6 | **3.26** | 4.80 | **-1.46 (MINLP loses 6/6)** |

So when the optimiser's output is actually used, MINLP wins every single time. When the pipeline
falls back to the anchor, it loses every single time. The "significant differences" you observed are
the size of the gap between a *uniform* random draw and a *priority-weighted* random draw, not a
failure of the optimisation idea.

## 3. Root causes, ranked

### C1. The refinement loop selects on prediction distance only, never on priority

`find_counterfactuals` (`minlp_search.py:2193-2264`):

```python
if anchor_distance <= float(self.epsilon):
    best_cf = anchor_cf                      # anchor becomes the incumbent
    best_distance = anchor_distance
...
improved = eval_info["distance"] < best_distance    # <-- distance only
if improved:
    best_cf = list(cf)
```

The anchor is a *priority-agnostic* random point. Once it is inside `epsilon` (which it is by
construction, `_generate_exemplar_in_range` accepts the first point within `epsilon`), an
SLSQP candidate can only replace it by being *strictly closer to the target*. A candidate that is
also inside `epsilon` but has 2x the priority is discarded. This single line explains all six losing
cells.

Worse: the loop `break`s at `target_reached` the moment any candidate is inside `epsilon`
(`minlp_search.py:2253`), so the search stops precisely when it becomes free to trade prediction
slack for priority.

### C2. The anchor is drawn uniformly, ignoring priorities

`_sample_candidate_in_allowed_region` (`minlp_search.py:1760`) draws numerical features uniformly
over the allowed intervals and categorical groups uniformly over allowed combos ("priority weights
are ignored on purpose"). Random search draws the same space with acceptance probability equal to
the priority weight. Expected priority of a uniform draw is far below that of a weighted draw when
the functions are peaked, exactly as measured in 2.2. Since the anchor is also the point all Shapley
values are computed against, a bad anchor degrades both the fallback CF *and* the guidance.

### C3. The dataset exemplar path never succeeded, so guidance is anchored on noise

`find_closest_elem` requires a priority-feasible dataset row within
`target_exemplar_epsilon = 0.10` of the target *after* filtering by all bounds and forbidden
categories (`get_rows_in_priorities`). It failed for 20/20 runs. Shapley values are then computed
between the sample and a random point, and the coefficient is a secant slope
`phi_i / (exemplar_i - sample_i)` (`minlp_search.py:1239`) whose denominator is a random number.
That makes the linear coefficients noisy and scale-unstable (near-zero denominators are clamped to
coefficient 0, silently freezing that feature's influence in the surrogate).

### C4. The surrogate constraint is too inaccurate for the step sizes taken

`warm_start_best_model_gap` of 0.02-0.40 vs `epsilon = 0.05` means the point that satisfies the
linearised constraint exactly is far outside the true band. SLSQP then *maximises priority on the
boundary of that wrong feasible set*, i.e. it pushes features as far as the surrogate allows,
precisely where the linearisation error is largest. There is no trust region: the loop
re-linearises (`minlp_search.py:2264`) but never limits the step length, so it oscillates or lands
outside `epsilon` and loses to the anchor by C1.

### C5. The LP warm start is priority-blind

`solve_linear_constraint_lp` uses a zero objective (`c = np.zeros(n)`, `minlp_search.py:1104`):
it returns an arbitrary feasible vertex/interior point. SLSQP is a local method started from that
arbitrary point, while the priority landscape is multi-modal (sum of peaked, plateaued, and
gapped functions). One arbitrary start per sample means one local optimum.

### C6. Non-smooth objective and constraints break SLSQP's gradients

* `objective_wrapper` returns `-1e12` when `calculate_total_weight` raises (value outside
  `[min, max]` or inside a zero-priority gap), so the objective has a `1e12` cliff
  (`minlp_search.py:1980`). Finite-difference gradients across that cliff are meaningless and SLSQP
  stalls at the first probe that crosses it.
* Allowed intervals are enforced with `max(min(v - lo, hi - v))` (`_allowed_interval_constraint_value`),
  which is non-smooth (max of mins), for a solver that assumes smooth constraints.
* Priority functions built from plateaus/trapezoids have zero gradient over wide regions, so SLSQP
  gets no descent information for exactly the features that matter.

### C7. Multi-candidate selection has an inverted sign (latent bug)

`_select_best_candidate` (`minlp_search.py:2063-2085`) picks `min(calculate_total_weight)` while
SLSQP maximises the same quantity (`objective_fun = -objective_wrapper`). The docstring calls it
"priority cost", but `calculate_total_weight` is the priority *benefit* summed with
`compute_priority_score`'s semantics. With more than one categorical combination this deliberately
returns the **worst** candidate. Diabetes has a single surviving combo
(`warm_start_total_combos == 1`) so this run is unaffected, but any dataset with real categorical
branching is.

### C8. Categorical pruning discards high-priority categories

`create_limited_priorities` keeps only the sample's and the exemplar's category per group. A
category with a much higher priority weight that appears in neither is unreachable for MINLP, while
random search samples it proportionally to its weight. Again not binding for diabetes
(one group, `sex`), but it caps MINLP's achievable priority in general.

## 4. Why random search is stronger than "just random"

It is an importance sampler over the priority distribution plus a validity filter:

* numerical: `sample_numeric_value` does rejection sampling with acceptance probability equal to the
  priority value, falling back to inverse-transform on a 256-point grid, so the marginal density is
  proportional to the priority function;
* categorical: combos are drawn with probability proportional to their weights;
* only draws within `epsilon` of the target are kept, and up to 10,000 draws are attempted per CF.

Given a priority landscape with wide plateaus at the maximum (the `s*` features here), such a
sampler collects near-maximal per-feature credit almost for free. That is a genuinely strong
baseline in ~9 effective dimensions, and it is the right baseline, but note its opposite bias: it
under-samples feasible-but-low-priority regions. Evidence: set2 samples 52 and 60 are feasible
(`minlp_feasibility.csv: feasible_within_epsilon = True`) yet random search returned nothing while
MINLP did.

## 5. Experimental-design caveats affecting the table

1. **Best-of-5 vs best-of-1.** Random search requests `n_cfs = 5` and the comparison uses the best
   (or per-CF) priority, while MINLP is clamped to a single output. Max-of-5 draws from a
   priority-weighted sampler is a materially stronger statistic than one draw; the per-sample
   `rs_mean` column above is 0.3-0.7 lower than `rs_max`.
2. **Unequal budget.** Random search uses up to 10,000 model evaluations per CF (observed
   `iterations` up to 8,418). MINLP uses ~200 Shapley subsets x units x refinement passes plus
   SLSQP evaluations, and stops after 1-5 passes. Neither wall-clock (1.06 s vs 8.73 s) nor
   evaluation counts are matched.
3. **Shared mutable priorities.** `runner.run_experiment` builds `priorities` once per sample and
   passes the same dict to the feasibility probe, MINLP and random search. Stage 0
   (`_derive_bounds_and_intervals_from_priorities`) mutates `cfg["min"]/["max"]/["allowed_intervals"]`
   in place, so by the time random search runs, its sampling range has already been trimmed to the
   positive-priority support by MINLP's preprocessing. This only removes zero-priority tails
   (so it does not distort the comparison in random search's favour on *quality*), but it does raise
   its acceptance rate, and any future Stage 0 change would silently alter the baseline.
4. **Metric direction.** `metrics_summary.csv` averages priority over *valid* CFs only, so a method
   that produces fewer but easier CFs looks better on the average. Compare per-sample paired deltas
   (as in 2.1) rather than method-level means.

## 6. How MINLP could actually leverage its optimisation machinery

Ordered by expected gain per unit of work.

**Hard constraints on any proposal** (given by the experiment's purpose):

1. Random search must not be used inside MINLP in any form. Any point that reads "sample the
   priority distribution" is therefore ruled out; ideas below use *deterministic* constructions
   (priority-function argmax, LP vertices, dataset rows) instead.
2. Shapley values stay the source of guidance. They must not be replaced by gradients of the model.
   Where a proposal needs a local slope it must come from Shapley values computed against a closer
   reference point, not from `tf.GradientTape` / finite differences of the model.
3. True-model calls must stay as low as possible. Every proposal below states its model-call cost;
   the model is used only to *verify* and to *measure the surrogate residual*, never as the
   optimiser's constraint function.

Points that violate 1 or 2 are kept in the list but explicitly marked **[ruled out]** so the
reasoning stays on record.

### A. Fix selection so priority is the objective it claims to be (**IMPLEMENTED**)

1. Keep two incumbents in `find_counterfactuals`: `best_feasible` ranked by **priority score**
   among candidates with `|f(x) - target| <= epsilon`, and `best_infeasible` ranked by distance.
   Return `best_feasible` if any exists; only fall back to distance ranking when none does.

   ```python
   feasible = eval_info["distance"] <= self.epsilon
   score = self.calculate_total_weight(cf)          # already available
   if feasible and (best_feasible is None or score > best_feasible_score):
       best_feasible, best_feasible_score = list(cf), score
   ```

2. Never return the anchor silently. If the anchor wins, record `cf_source = "anchor"` and
   `priority_gain_vs_anchor = 0` so the metrics stop crediting the optimiser for a random draw.
   (The runner already has the columns to expose this.)
3. Do not `break` on `target_reached`. Once inside the band, keep iterating with the priority
   objective and the band as a hard constraint; stop on priority stagnation instead
   (`patience` on `score`, not on `distance`).
4. Fix the `_select_best_candidate` sign (C7): pick `max(calculate_total_weight)`, and rename the
   variables/docstring to "priority benefit" to prevent the same confusion recurring.

### B. Anchor and warm start

5. **[ruled out - constraint 1]** Replace the uniform fallback anchor with a priority-weighted
   sampler. This is random search inside MINLP and would make the comparison meaningless. Kept here
   only to record that the anchor's weakness must be fixed by *optimising away from it*
   (points G, C) rather than by drawing a better anchor.
6. **[ruled out - constraint 1]** Multi-start from *k* weighted random draws. The deterministic
   replacement is point E17 (multi-start from priority-peak combinations).

7. **Give the warm-start LP a priority objective** (currently `c = np.zeros(n)`,
   `minlp_search.py:1104`).

   **Where in the algorithm.** Inside Stage 4.5, i.e. *after* the Shapley values of Stage 3 have
   been turned into linear coefficients and a per-combination LP target, and *before* the SLSQP
   optimisation of Stage 5 starts. Only the LP's objective row changes; the constraint and the
   bounds stay exactly as they are.

   **How it works today.**

   ```
   Stage 3: Shapley  ->  coefficients c_i  (e.g. sample 38 set1:
                          c_age=+0.0398, c_bmi=+0.1978, c_bp=-0.0437,
                          c_s1=-0.1107, c_s2=+0.0547, c_s3=-0.0140,
                          c_s4=+0.1026, c_s5=-0.0170, c_s6=+0.0219)
        |
        v
   Stage 4.5: linprog( objective = ZEROS,
                       constraint: sum_i c_i x_i = adjusted_target,
                       bounds:     x_i in [min_i, max_i] )
        |
        v
   "some" feasible x0  (linprog stops at the first basic/presolved point;
                        its priority is accidental, often ~= the original point)
        |
        v
   Stage 5: SLSQP starts from that x0
   ```

   **How it would work.**

   ```
   Stage 4.5: build, per feature, a 3-4 breakpoint piecewise-linear model of its
              priority function on each allowed interval, e.g. for s4 on
              [-1.61, -0.386]:  p(-1.61)=0.00 , p(-0.386)=0.70  (peak)
        |
        v
              linprog( objective = MAXIMISE sum_i p_i(x_i)   [epigraph form:
                       one aux variable + 2-3 rows per feature],
                       constraint: sum_i c_i x_i = adjusted_target,     <- unchanged
                       bounds:     x_i in [min_i, max_i] )              <- unchanged
        |
        v
   x0 = the priority-best point that the Shapley model says still hits the target
        |
        v
   Stage 5: SLSQP starts from a point that is already near-optimal in priority
   ```

   **Numeric example (sample 38, set1).** The peaks are
   `age 1.9213 (0.984), bmi -0.6941 (0.498), bp 0.07 (0.498), s1 -0.576 (0.698),
   s2 -0.5587 (0.695), s3 -1.7975 (0.688), s4 -0.3855 (0.700), s5 -0.6256 (0.697)`,
   so the piecewise-linear priority optimum is ~6.5. The LP as it stands returned a start whose
   priority was 3.26; with the priority objective the LP itself would already propose a point in the
   5.5-6.5 range that satisfies `sum_i c_i x_i = adjusted_target`.

   **After this change** the pipeline continues unchanged into Stage 5 (SLSQP) and Stage 6
   (candidate selection), then into the section A incumbents and the Stage 7 sweep of point G. The
   expected effect is that the *first* SLSQP pass already lands close to the priority optimum, so
   fewer refinement passes (and therefore fewer Shapley re-computations, i.e. fewer model calls) are
   needed. Cost of the change itself: **0 model calls**, LP only.

8. **Repair the dataset exemplar path.** `find_closest_elem` failed 20/20 times, so Shapley values
   are always anchored on a random point.

   **Where in the algorithm.** Stage 1, the very first step after Stage 0 has derived the allowed
   intervals: the choice of the *target exemplar*, which is the reference point every Shapley value
   in Stage 3 is computed against.

   **How it works today.**

   ```
   Stage 1.1: drop training rows with a forbidden category
              drop training rows outside [min_i, max_i] of every feature
                     -> for diabetes this empties the set, or leaves rows whose
                        prediction is far from the target
   Stage 1.2: keep the row with min |f(row) - target|
              if that distance > target_exemplar_epsilon (0.10) -> FAIL
                     -> fallback: uniform random in-range point ("random_in_range",
                        used in 20/20 runs)
   ```

   **How it would work.**

   ```
   Stage 1.1': first select rows with |f(row) - target| <= target_exemplar_epsilon
               (prediction filter FIRST, so the candidate pool is never emptied by
                the priority filter)
        |
        v
   Stage 1.2': project each candidate row into the allowed region
               (_project_to_allowed_intervals already exists) and score it with
               calculate_total_weight
        |
        v
   Stage 1.3': pick the candidate with the HIGHEST priority (not the closest
               prediction) as the exemplar; only if the pool is empty fall back to
               the current random in-range anchor
   ```

   **Numeric example.** For sample 38 the exemplar actually used was a random point with priority
   ~1.8-2.6, and the Shapley secant was taken over that random direction. A projected training row
   with priority 4-5 would give both a better anchor and a data-supported direction, without any
   change to how Shapley values are computed.

   **After this change** Stage 3 computes Shapley values against a real, high-priority data point,
   Stage 4/5 inherit better coefficients, and the "anchor" fallback of section A becomes rare. Cost:
   the same single batch prediction over the training set that `find_closest_elem` already performs.

### C. Make the Shapley surrogate trustworthy (medium effort, unlocks the optimiser)

This is where the three remaining losses live: the surrogate is off by 0.15-0.48 at the points
SLSQP likes, against `epsilon = 0.05` (2.3). All three points below keep Shapley as the only source
of slope information and add at most one or two model calls per iteration.

9. **Trust region on the step length.**

   **Where in the algorithm.** Inside Stage 5 (the SLSQP subproblem) plus the accept/reject decision
   that follows it in the refinement loop. It changes *how far* one pass is allowed to move, not what
   it optimises.

   **How it works today.**

   ```
   iterate x^k (Shapley computed here)
        |
   Stage 5: SLSQP: max priority(x)  s.t.  h(x) in [target-eps, target+eps],
                                          x in [min, max]        <- whole box!
        |
        v
   x^+ can be at the far corner of the box, e.g. sample 52:
        h(x^+) = 0.0381  (surrogate says: on target 0.0185)
        f(x^+) = 0.5230  (model says: 0.48 away)
        |
        v
   section A: |f - target| > eps  ->  candidate discarded, anchor returned
   ```

   **How it would work.**

   ```
   iterate x^k, trust radius Delta (start: 25 % of each feature's allowed span)
        |
   Stage 5': SLSQP: max priority(x)  s.t.  h(x) in band,
                                           |x_i - x_i^k| <= Delta_i    <- NEW
        |
        v
   one model call: f(x^+)
        |
        +-- rho = (f(x^+)-f(x^k)) / (h(x^+)-h(x^k))
        |
        +-- rho in [0.5, 1.5] and in band  ->  ACCEPT x^{k+1} = x^+, Delta *= 2
        |
        +-- otherwise                      ->  REJECT, keep x^k,     Delta *= 0.5
        |
        v
   Stage 3 re-linearises Shapley at the accepted iterate and the loop repeats
   ```

   **Numeric example (sample 60, set1).** The unconstrained pass produced a point at true distance
   0.2831 with priority 6.58 (discarded today). Walking that same direction and measuring the model
   shows where the surrogate stops being valid:

   | fraction of the step | true distance | priority | in band? |
   |---|---|---|---|
   | 0.50 | 0.0086 | 3.55 | yes |
   | 0.625 | 0.0441 | 3.95 | yes |
   | 0.6328 | 0.0490 | 3.98 | yes |
   | 0.6875 | 0.0932 | 4.21 | no |
   | 0.75 | 0.1378 | 4.51 | no |
   | 1.00 | 0.2831 | 6.58 | no |

   A trust region of about `0.6 x step` would have accepted the 0.63 point (priority 3.98 vs the
   anchor's 2.67) instead of discarding everything, and then re-linearised Shapley *there* and taken
   the next step from a better place.

   **After this change** the loop keeps its structure (Stage 3 -> 4 -> 5 -> 6 -> accept/reject) but
   each pass is a genuine improvement step, so `cf_source` should become `optimiser` everywhere and
   the anchor stops mattering. Then the Stage 7 sweep of point G runs on a much better incumbent.
   Cost: 1 model call per pass, which the loop already spends.

10. **Additive residual correction of the surrogate (zero extra model calls).**

    **Where in the algorithm.** In `constraint_function` / the LP target, i.e. between Stage 4.3
    (build the LP target) and Stage 5 (SLSQP), from the *second* refinement pass onwards, once one
    model evaluation of the previous iterate exists.

    **How it works today.**

    ```
    Stage 4.3 target for the surrogate:      h(x) = target
    Stage 5 optimises against h              (the mismatch f - h is never used)
    Stage "verify": f(x^+) measured, mismatch computed for the CSV only, then thrown away
    ```

    **How it would work.**

    ```
    after the model call of pass k:   r^k = f(x^k) - h(x^k)          <- already measured
        |
        v
    pass k+1 aims the surrogate at:  h(x) = target - r^k
        (equivalently uses h_corr(x) = h(x) + r^k inside the band constraint)
        |
        v
    Stage 5 now optimises against a surrogate that reproduces the model at x^k exactly
    ```

    **Numeric example (sample 52, set1).** Target `0.0185`, measured at the candidate:
    `h = 0.0381`, `f = 0.5230`, so `r = +0.4849`. Today pass k+1 again aims at `h = 0.0185` and again
    lands ~0.5 away. With the correction it aims at `h = 0.0185 - 0.4849 = -0.4664`, i.e. it asks the
    Shapley model for a *much* stronger prediction decrease, which is what the true model actually
    needs. Together with the trust region of point 9 the residual `r^k` stays small (the step is
    small) and the correction converges instead of oscillating.

    **After this change** nothing else in the pipeline moves: Stage 5 still maximises priority,
    Stage 6 still selects, section A still ranks by priority, Stage 7 still sweeps. Cost: **0**
    additional model calls.

11. **Local Shapley re-anchoring** (replaces the earlier "use model gradients" idea, which is
    **[ruled out - constraint 2]**; Shapley stays, only the reference point moves closer).

    **Where in the algorithm.** Stage 3, the Shapley computation itself, and Stage 4.3, where the
    Shapley value is divided by the feature difference to become a linear coefficient.

    **How it works today.**

    ```
    exemplar chosen ONCE in Stage 1 and never moved
        |
    Stage 3: phi_i = Shapley( sample  <->  exemplar )
        |
    Stage 4.3: c_i = phi_i / (exemplar_i - sample_i)          <- a secant over the
        |                                                        WHOLE distance
        |      if |exemplar_i - sample_i| < 1e-12: c_i = 0    <- feature silently frozen
        v
    Stage 5 uses c_i to extrapolate to points that may be nowhere near that segment
    ```

    **How it would work.**

    ```
    at each accepted iterate x^k:
        pick a SHORTENED reference  r_t = x^k + t (exemplar - x^k),  t ~ 0.25-0.5
        (or exactly the trust-region distance of point 9)
        |
    Stage 3': phi_i = Shapley( x^k  <->  r_t )        <- same Shapley machinery,
        |                                                shorter interval
    Stage 4.3': c_i = phi_i / (r_t,i - x_i^k)         <- now a LOCAL slope
        |
        |   if the difference is ~0, widen only that feature's interval instead of
        |   setting c_i = 0
        v
    Stage 5 extrapolates only inside the region the secant was measured on
    ```

    **Numeric example.** Sample 52: the exemplar direction spans 0.30 of prediction range and the
    resulting linear model errs by **0.48** at the SLSQP solution. In the bisection probe the same
    model was accurate to ~0.01 when evaluated at half the distance, which is exactly what a
    shortened reference gives you. Concretely, if `c_bmi = 0.1978` was measured over
    `bmi: 0.61 -> -0.75` (a span of 1.36), remeasuring over `0.61 -> -0.07` (span 0.68) gives a slope
    valid for the steps the trust region will actually take.

    **Model-call cost note (constraint 3).** Approximate Shapley with `num_samples = 200` and 10 units
    costs ~4,000 model rows per re-linearisation and dominates the whole method's model usage.
    Mitigations that keep Shapley intact: (a) antithetic / permutation-balanced subset sampling
    (same variance at 50-80 samples), (b) skip re-linearisation when the accepted step is a small
    fraction of `Delta`, (c) cache every model evaluation keyed by the rounded feature vector, since
    the subset batches repeat heavily.

    **After this change** the surrogate that Stages 4 and 5 rely on is locally faithful, so the trust
    region of point 9 can grow instead of shrinking, and fewer passes are needed overall.

12. **Restoration line search (keeps every priority gain).**

    **Where in the algorithm.** Right after Stage 6 produced a candidate and the single verification
    model call showed it is *outside* the band, i.e. exactly the moment where the current code throws
    the candidate away. (Note: point G already implements the same idea for its single-feature swaps;
    this generalises it to the full SLSQP candidate.)

    **How it works today.**

    ```
    candidate x^+ : priority 6.58 , |f(x^+) - target| = 0.2831 > eps
        |
        v
    discarded entirely  ->  anchor (priority 2.67) is returned
    ```

    **How it would work.**

    ```
    candidate x^+ outside the band, residual r = f(x^+) - target
        |
        +--(a) one Shapley-Newton restoration step:
        |       x <- x^+ - r * c / ||c||^2        (c = Shapley coefficient vector;
        |                                          no model gradient involved)
        |       1 model call -> in band? keep it
        |
        +--(b) else bisect on the segment [x^k , x^+] for at most 3-4 steps,
        |       keeping the last in-band point
        v
    the best in-band point on that path enters the section A priority ranking
    ```

    **Numeric example (sample 60, set1).** Four bisection steps on the discarded candidate give
    priority 3.95 at distance 0.0441 (in band), instead of falling back to the anchor's 2.67, for
    4 model calls, spent only on candidates that would otherwise be wasted.

    **After this change** every SLSQP pass contributes something, so the incumbent that Stage 7
    (point G) refines is already close to the band's priority optimum.

### D. Respect the actual MINLP structure (medium effort, removes non-smoothness)

13. **Branch over the discrete structure** instead of encoding it as non-smooth constraints.

    *Current workflow.* A feature whose priority function has two separated positive intervals, say
    `[-2.3, -1.5]` and `[0.2, 0.9]`, is handled with a single box `[-2.3, 0.9]` plus the non-smooth
    inequality `max(min(v - lo, hi - v)) >= 0` and a `-1e12` objective cliff for the gap in between.
    SLSQP has to discover the gap by trial and error, and its finite differences straddle it.

    *Planned workflow.* Enumerate the interval assignments (one interval per feature) together with
    the categorical combinations, and solve one smooth NLP per assignment with plain box bounds
    `[lo, hi]` and no interval constraint at all. That is literally the "MIN" of MINLP. Prune
    assignments whose linearised prediction range cannot reach the target (a one-line interval-
    arithmetic test with the Shapley coefficients: `sum_i min/max of c_i x_i` must bracket the
    target), so the count stays small.

    *Numeric example.* If 3 of 9 features have 2 positive intervals each, that is 8 subproblems, and
    the bracketing test typically removes half of them. Model calls: unchanged (the surrogate does
    the pruning), plus one verification per surviving solution.
14. Replace the `-1e12` penalty with either hard bounds per subproblem (see 13) or a smooth
    quadratic penalty, and supply analytic gradients of the priority functions where they exist
    (they are built analytically in `priority_sets.py`).
15. Where priorities are plateaued, add a tie-break term (e.g. `-lambda * ||x - x_orig||_1`) so the
    solver gets gradient information and prefers small changes at equal priority. This would also
    fix MINLP's worse `avg_l1`.

### E. Escape the plateaus deterministically

16. **[ruled out in its stochastic form - constraint 1]** `differential_evolution` / basin hopping
    on the priority objective. These are randomised global searches over the same space random
    search explores, so they blur the comparison. The deterministic alternatives are E17 and G.

17. **Deterministic multi-start from priority-peak combinations.**

    *Current workflow.* One start per categorical combination, taken from a priority-blind LP
    (`warm_start_total_combos == 1` for diabetes, so literally one start per sample).

    *Planned workflow.* Enumerate a small, deterministic set of starts:
    (a) the priority-ideal point (every actionable feature at its priority argmax, best categorical
    combination); (b) for each actionable feature, the point with only that feature at its peak and
    the rest at the current iterate; (c) one point per allowed-interval assignment when a feature's
    priority function has several separated positive intervals. Project each onto the linearised
    constraint with the LP of B7, run the trust-region loop from each, keep the priority-best
    feasible result. For diabetes this is ~10-20 starts, all deterministic and reproducible.

    *Numeric example.* The priority-ideal point has priority ~6.58 (set1) and ~5.59 (set2) versus the
    2.4-4.4 the current search settles at in the stuck cells. It is itself infeasible
    (`f(ideal) = 0.63` vs target 0.11 for sample 60, and the straight segment from the original
    sample never crosses the band), which is exactly why it must be used as a *start* for the
    corrected trust-region loop rather than as a candidate.

### G. Greedy peak lock-in with Shapley compensation (new; cheapest and strongest next step)

**Status: IMPLEMENTED (step 1). The full walkthrough, with the code-level changes and the measured
results, is section 8 of this document.** The summary below states where in the algorithm it sits
and why it works; section 8 explains it step by step with real numbers.

**Where in the algorithm.** *After* the MINLP refinement loop has finished (Stages 3-6 have run
their passes and section A has chosen the best in-band counterfactual), and *before* the
counterfactual is returned to the runner, we take that in-band point and keep trading feature values
against each other, using the Shapley coefficients as the exchange rate, until no trade improves the
priority any more. Nothing before Stage 6 is touched, so this cannot change validity, feasibility or
the number of counterfactuals found; it can only raise the priority of a counterfactual that is
already valid.

**Why it works.** The priority functions in these sets come in two shapes: narrow peaks
(`age`, `bmi`, `bp`, whose peak often sits at the original value) and wide plateaus at the maximum
(`s1`..`s6`). Moving a plateau feature inside its plateau changes the prediction but costs no
priority, so it can *pay* for putting a peaked feature exactly on its peak. SLSQP cannot see this:
on a plateau the priority gradient is exactly 0, so it has no reason to move there, and its
continuous all-features-at-once step is judged against a surrogate that is wrong at that scale.

**Result:** 13/13 comparable cells now beat random search (set1 8/8, set2 5/5) for 0-41 extra model
calls per sample. See section 8.6.

## 8. Step 1 implemented: Stage 7, peak lock-in with Shapley compensation (point G)

### 8.1 Vocabulary used in this section

These terms are used throughout; they are defined here because the earlier sections assumed them.

| term | meaning in this code base |
|---|---|
| **pass** (was called "iteration") | one turn of the refinement loop `while iteration < max_iterations`: recompute Shapley (Stage 3) -> build the LP warm start (Stage 4) -> run SLSQP (Stage 5) -> pick a candidate (Stage 6). `max_iterations = 10`, so up to 10 passes per sample. |
| **last pass** | the most recent completed pass, i.e. the pass whose Shapley coefficients `sample_state.shap_coeffs` are currently stored on the explainer. Stage 7 reuses exactly those, so it needs **no** new Shapley computation. |
| **candidate** | the point SLSQP returned in one pass, before it is checked against the real model. |
| **incumbent** | the best point kept across passes. Since step 0 (section A) there are two: `best_feasible` (the best point that is *inside* the target band, ranked by priority) and `best_infeasible` (the closest-to-target point when nothing landed inside the band, ranked by distance). "The incumbent `x`" in section 6 always means `best_feasible`. |
| **anchor** | the target exemplar used as the Shapley reference. On this dataset it is always `random_in_range`, i.e. a uniformly sampled in-range point (see 2.1). If no candidate is ever feasible, the anchor itself becomes `best_feasible`, which is what `cf_source == "anchor"` records. |
| **band** | the accepted prediction interval `[target - epsilon, target + epsilon]`, with `epsilon = 0.05`. "In band" = the *real* model prediction lies inside it. |
| **`h(x)` / `f(x)`** | `h` is the Shapley surrogate (`constraint_function`), `f` is the real model (`model_pred`). |
| **peak** | the value at which a single feature's priority function is maximal, `peak_i = argmax_v p_i(v)`, found by a 1000-point grid scan over that feature's allowed intervals. Costs **0** model calls (priority functions are analytic). |
| **plateau feature** | a feature whose priority stays (nearly) at its maximum over a wide range, e.g. `s1`..`s6` here. Moving it inside the plateau changes `f` but costs no priority. |

### 8.2 Where the change sits in the pipeline

The added code is a new **Stage 7** that runs once, after everything else, on the feasible incumbent.

```
Stage 0  derive allowed intervals from the priority functions
Stage 1  choose target exemplar (anchor)                       [unchanged]
Stage 2  log bounds                                            [unchanged]
   |
   |  refinement loop, up to max_iterations passes:
   +--> Stage 3  Shapley values -> coefficients c_i            [unchanged]
   +--> Stage 4  warm-start LP per categorical combination     [unchanged]
   +--> Stage 5  SLSQP: maximise priority s.t. h(x) in band    [unchanged]
   +--> Stage 6  select candidate, one real model call          [unchanged]
   |             update best_feasible / best_infeasible        [step 0 / section A]
   v
Stage 7  PEAK LOCK-IN  <-- NEW (this section)
         input : best_feasible (in band, priority-ranked)
                 + the Shapley coefficients c_i of the LAST PASS
         output: a point that is still in band with a >= priority
   |
   v
assemble last_search_result: cf_source, priority_gain_vs_anchor, peak_lock_in{...}
```

Stated as the user asked: **after the MINLP has produced a point that the real model confirms is
inside the band, but whose priority is poor because SLSQP could not exploit the plateaus, we take
that point and trade plateau features against peaked features until no trade helps.** If the MINLP
never produced an in-band point at all (`reached_target == False`), Stage 7 is skipped entirely.

### 8.3 The algorithm, step by step

```
step 1 -> x := best_feasible ; P := priority(x) ; load c_i from the last pass
step 2 -> compute peak_i and p_i(peak_i) for every actionable feature   [0 model calls, cached]
step 3 -> sort features by how much priority they can still gain:
             gain_i = p_i(peak_i) - p_i(x_i)          (largest first)
step 4 -> for the next feature i in that order:
step 5 ->     propose x_i := peak_i
              the surrogate says the prediction moves by  dh = c_i * (peak_i - x_i)
step 6 ->     for every other feature j, the value that would cancel dh is
                  v_j = clip( x_j - dh / c_j )
              and its priority cost is  cost_j = p_j(x_j) - p_j(v_j)
              keep the candidates with cost_j < gain_i, cheapest first
step 7 ->     try up to 3 cheapest compensators j:
step 8 ->         build the trial point (x with x_i = peak_i and x_j = v_j)
                  ONE real model call -> pred
step 9 ->         if |pred - target| > epsilon:
                      one restoration step on j using the MEASURED residual r:
                          x_j := clip( x_j - r / c_j )
                      ONE more real model call -> pred
step 10 ->        accept iff |pred - target| <= epsilon AND priority(trial) > P
                  (otherwise discard the trial and try the next compensator)
step 11 ->    if accepted: x := trial ; P := priority(trial) ; go to step 4
step 12 -> after a full sweep over all features, if at least one move was accepted
           start another sweep (max 3 sweeps); otherwise stop and return x
```

Properties that follow directly from step 10: the returned point is always in band, its priority is
always `>=` the priority of the point Stage 6 produced, and the search is deterministic (no random
number is drawn anywhere in Stage 7, satisfying constraint 1). The only guidance signal is the
Shapley coefficient vector `c` (constraint 2), and the model is called at most twice per attempted
move (constraint 3).

### 8.7 What this does *not* fix

Stage 7 repairs the *result*; it does not repair the search. The `anchor+peak_lock_in` rows show the
MINLP loop itself still failed to produce an in-band SLSQP candidate, because the Shapley surrogate
is wrong at the scale of the step it takes (2.3, C9-C11). Concretely, the loop's own candidates on
sample 38 had priority 5.2-6.6 with true distances 0.06-0.55 against `epsilon = 0.05`. Step 2 of
section 7 (trust region + additive residual correction) addresses that; when it lands, Stage 7 should
start from an `optimiser` point every time and its remaining job should shrink to a final polish.
